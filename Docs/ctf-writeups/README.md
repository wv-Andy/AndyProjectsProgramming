# CTF Write-ups

Documented solutions to Capture The Flag challenges: the reconnaissance, the
attempts that failed, the working exploit, and the fix.

The write-up is the point, not the flag. Anyone can follow a walkthrough. Writing
your own turns a solved box into something another person can learn from, and it
is the skill that separates a hobbyist from someone who can explain their work in
an interview.

## How to use this folder

1. Solve a challenge on a legal platform (see below).
2. Copy [`TEMPLATE.md`](TEMPLATE.md) to a new file named for the box, such as
   `tryhackme-blue.md`.
3. Fill it in **as you go**, not afterwards. The failed attempts are the most
   valuable part, and they are gone from memory an hour later.

## Legal platforms

Only ever practise on systems built for it. These are legal, free to start, and
designed to be attacked:

- **TryHackMe** — guided rooms, good for starting out
- **Hack The Box** — less hand-holding, closer to real engagements
- **PicoCTF** — Carnegie Mellon's beginner CTF, especially strong on fundamentals
- **OverTheWire** — wargames that teach Linux and privilege escalation
- **VulnHub** — downloadable vulnerable VMs you run locally

Never point these techniques at a system you do not own or have written
permission to test. The line between a CTF and a crime is authorisation.

## The methodology

Every write-up in this folder follows the same phases, described in
[`methodology.md`](methodology.md). Following a consistent method is what makes
the difference between poking at a box and working it systematically.

## Why this belongs in the portfolio

Two reasons. It shows applied skill, using the tools in this repository and
others against real targets. And it shows you can write, which is half of every
security job: a finding nobody can understand is a finding nobody will fix.
